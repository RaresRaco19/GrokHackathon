High-level design

The desk is a local decision system on one laptop, not a hosted insurer platform. Five faces share one path: CLI, tests, website, Grok Build chat, and Grok Bot. All quote the same kit file. None invent rules. None state a payout. Kit files were inspected on 2026-09-18. Quotes are always read from policy-excerpt.md at runtime.

Purpose

Decide FNOL reports. CL-03 glass → open PX-GLASS. CL-04 flood → refuse PX-FLOOD scoring case. Never a payout.

Actors

Intake clerk (opens, asks, confirms). Judge (live pass + refuse, must-show). Grok Build. Intake Clerk bot (night watch).

Source of truth

policy-excerpt.md is the only rule book. fnol.json is the only report data. Do not rewrite either.

Outcomes

open hold for photos refuse draft until confirm

Win pick. Track 4.3 plus Intake Clerk. Derived scoring (not official weights and not a judge promise; see track-scoring.html): 4.3 with Bot modeled at a 20/20 ceiling. Official judging has no published points. Scoring case is CL-04. Any dollar amount zeros Decisions.

Detailed design

Detailed design is the decision path, Grok surfaces, website backend, confirm-before-send, and the Bot. Chat and the UI are not allowed a second policy memory. Policy bodies come from the file at runtime — not as a second book in JS or the skill.

  1. Payout / settlement / “we will pay” → refuse, quote PX-NO-PAY. Medical/legal → refuse with No rule line matched. plus a fixed coverage-only sentence. Off-desk JSON uses rule_id: null.
  2. Load the report (id, peril, photos, cover). Lookup cover in load_policy().
  3. cover == PX-FLOOD → refuse (CL-04). Photos true does not override.
  4. photos === false → hold for photos (CL-08). Quote PX-COLLISION (“Need photos”). Collision is hold-only when photos are false. Do not invent open-collision.
  5. cover == PX-GLASS → open (CL-03).
  6. No matching line → say so. One algorithm: cover-id lookup, not token scan.

GET /api/queue is read-only. Refuse logging happens in ensure_state(), not on GET. Only POST /api/confirm mints a claim number.

CLI path

bin/run.sh selects a case. python/decide.py parses the policy file, applies the order above, prints clerk view or JSON.

Website path

bin/desk.sh starts python/serve_desk.py on 127.0.0.1:8788. UI fetches queue / ask / confirm / log. The page does not contain policy bodies.

Chat path

Grok loads AGENTS.md and review-fnol, calls MCP lookup_rule, then applies the same order. Output must match the script.

Bot path

Intake Clerk is a briefed teammate. Wait-for-yes. Refuse logged not sent. Does not mint. Laptop POST /api/confirm is the only mint.

If this went live

Three sentences judges ask. Shown in the website, not only spoken.

1. Who clicks before it sends

The intake clerk. open and hold for photos stay draft until that human confirms. The engine never mints a claim number by itself. Refuse is logged, not sent — no click, no claim number.

2. How you undo a bad change

Revert the report to draft. The claim number is cleared. History is appended, not deleted. Kit files roll back with git. The hook already refuses edits to policy-excerpt.md.

3. What you write in a log

Claim id, decision (open / hold / refuse), verbatim policy quote, timestamp, optional claim number. No amount.
