Module 4.3 · claim intake

How the Grok agent reaches the rules MCP

The model never opens policy-excerpt.md. It asks for a tool. The host runs that tool on local rules_mcp.py over JSON-RPC. The quote comes back, then Grok returns open, hold, or refuse. Nobody names a payout.

Invariant lookup_rule on every inquiry. Confirm is the only mint. Kit stays at repo root.

Two doors, one server

Grok Build and the HTTP desk are different hosts. Both spawn the same MCP process and read the same excerpt.

Host → MCP (JSON-RPC tools/call) MCP → host (verbatim quote) MCP ↔ policy-excerpt.md

One inquiry, one loop

Python does not decide coverage. Grok must call the tool. The validator only checks the receipt.

Golden cases

Same loop every time. The quote is a substring of the MCP result, not a remembered policy.

Live-ops

The agent stops at the decision. A human clicks confirm. That is the only mint.

GET

/api/queue — cached decisions only. Does not call Grok.

POST

/api/assess — Grok + MCP tools. Logs refuse once.

POST

/api/confirm — mints FNOL-{id}-{UTC} on open only. CL-04 → 400.

POST

/api/undo — restore draft, clear claim number.

GET

/api/log — JSONL. No amount, payout, or $ keys.

GET

/api/health — MCP reachable via list_rules.

Guardrails around the pipe

Prompt
AGENTS.md

MCP before decide. Structured JSON block. Scope fence on payout, medical, legal. Stop before mint.

Skill
/review-fnol

Walks fnol.json, one rules__lookup_rule per row, same JSON decision contract as the API.

Hook
enforce_rules.py

Stop-blocks skip-MCP, invented PX-* ids, payout promises. Denies edits to the excerpt and extra rule books.

Validator
Receipt check, not a second engine

Rejects skip-MCP, invented ids, and $ + digits / “we will pay” outside the quote. Does not re-derive flood or glass.
